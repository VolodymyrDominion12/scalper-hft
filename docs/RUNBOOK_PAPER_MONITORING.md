# Рунбук: Моніторинг демо-торгівлі (Paper Trading) через VPS API та локальний дашборд

> **Статус:** Робоча інструкція  
> **Призначення:** Організація 24/7 paper-моніторингу стратегій (наприклад, `pairs_arb` 1h maker) на VPS із безпечною трансляцією телеметрії на локальний Streamlit-дашборд.

---

## 1. Архітектурний принцип: хто що робить

Головне правило архітектури `scalper-hft` — **строге розділення виконання та візуалізації**:

```text
┌────────────────────────────── VPS (24/7) ─────────────────────────────┐
│                                                                       │
│  ┌──────────────────────────┐         ┌────────────────────────────┐  │
│  │    Paper Trading Bot     │         │       FastAPI Сервер       │  │
│  │ (systemd / CLI --daemon) │         │ (REST API + WebSocket /ws) │  │
│  └────────────┬─────────────┘         └──────────────▲─────────────┘  │
│               │ (запис барів,                        │                │
│               │  угод, позицій)                      │ (читання)      │
│               ▼                                      │                │
│       ┌──────────────────────────────────────────────┴──────┐         │
│       │      SQLite БД: results/paper_pairs.sqlite          │         │
│       │             (WAL-режим, PaperStore)                 │         │
│       └─────────────────────────────────────────────────────┘         │
│                                                              ▲        │
└──────────────────────────────────────────────────────────────┼────────┘
                                                               │
                                         Захищений SSH-тунель  │
                                         Port Forwarding: 8080 │
                                                               │
┌────────────────────── Локальний ПК (Ноутбук) ────────────────┴────────┐
│                                                                       │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                  Streamlit Dashboard (Локально)                 │  │
│  │                  Сторінка: "Live / WebSocket"                   │  │
│  │                                                                 │  │
│  │  • Читає REST / WebSocket через localhost:8080                   │  │
│  │  • Відображає баланс, PnL, маржу, графіки, список угод          │  │
│  │  • Передає команди: Пауза / Відновлення / Kill-Switch           │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

1. **Дашборд НЕ є базою даних і нічого не зберігає**. Він виступає лише як клієнт відображення (UI). Якщо ви вимкнете ноутбук чи закриєте браузер, бот на VPS продовжує безперервно торгувати.
2. **Бот на VPS — єдине джерело запису (Single Source of Truth)**. Кожен бар, кожне виконання, зміна балансу та знімок стану (`snapshot`) фіксуються в базу SQLite `results/paper_pairs.sqlite`.
3. **FastAPI сервер на VPS** читає дані з SQLite та миттєво транслює їх через WebSocket (`/ws`) та REST ендпоінти.
4. **Локальний ПК** підключається через зашифрований **SSH-тунель**, що гарантує 100% безпеку без відкриття портів у публічний інтернет.

## 2. Налаштування оточення (`.env`)

### На VPS (`.env`)
На сервері використовуються налаштування для автономного paper-демона:

```bash
# Режим демо-торгівлі
DRY_RUN=true
EXCHANGE=binanceusdm
DATA_EXCHANGE=binanceusdm

# Виконання (maker за замовчуванням)
MAKER_EXECUTION=true
MAKER_FEE=0.0002
TAKER_FEE=0.0005
SLIPPAGE_BPS=1.0

# Безпека API (мінімум 32 символи для HS256)
API_HOST=127.0.0.1
API_PORT=8080
API_SECRET_KEY=generate_a_very_secure_secret_key_at_least_32_chars_long

# Сповіщення Telegram
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-1001234567890
```

> [!IMPORTANT]
> Параметр `API_HOST=127.0.0.1` обов'язковий. Не вказуйте `0.0.0.0` на VPS без захищеного зворотного проксі (Nginx/TLS). Правило `require_safe_api_bind` блокує небезпечний bind.

### На локальному ПК (`.env`)
```bash
DRY_RUN=true
API_SECRET_KEY=той_самий_ключ_що_й_на_vps_не_менше_32_символів
```

## 3. Покрокова інструкція запуску

### Крок 1. Запуск торгового бота на VPS

Для стратегії парного арбітражу (`pairs_arb` 1h maker):

```bash
# Ручний запуск у фоні або через tmux/screen:
uv run python -m scalper_hft.cli paper-run-pairs --portfolio --daemon --notify
```

Або як системний сервіс systemd (рекомендовано для 24/7):
```bash
systemctl --user enable --now scalper-paper-pairs
systemctl --user status scalper-paper-pairs
```

---

### Крок 2. Запуск FastAPI сервера на VPS

Сервер транслює дані з SQLite в REST та WebSocket.

1. **Згенеруйте JWT-токен доступу для дашборду:**
   ```bash
   uv run python -m scalper_hft.cli api token --hours 720
   ```
   *Збережіть виведений JWT-токен — він знадобиться для входу в дашборд.*

2. **Запустіть API сервер на `127.0.0.1:8080`:**
   ```bash
   uv run python -m scalper_hft.cli api start --host 127.0.0.1 --port 8080
   ```

*(Опційно)* Можна створити systemd user-юніт для автостарту API на VPS: `deploy/scalper-api.service`.

---

### Крок 3. Створення захищеного SSH-тунелю (на локальному ПК)

Замість того, щоб відкривати порти сервера у світ, прокиньте порт через SSH:

```bash
ssh -N -L 8080:127.0.0.1:8080 user@YOUR_VPS_IP
```

*Параметр `-N` означає лише перенаправлення портів без відкриття віддаленого шелу. Поки ця команда активна, порт `8080` вашого ноутбука з'єднаний з портом `8080` сервера VPS.*

---

### Крок 4. Запуск локального дашборду (на локальному ПК)

У сусідньому терміналі на вашому комп'ютері:

```bash
uv run python -m scalper_hft.cli dashboard
```

1. Відкрийте у браузері адресу `http://localhost:8501`.
2. У лівому меню оберіть сторінку **«Live / WebSocket»**.
3. Розгорніть вкладку **«Параметри підключення до API та WebSocket»**:
   * **REST API URL:** `http://localhost:8080`
   * **WebSocket URL:** `ws://localhost:8080/ws`
   * **JWT Access Token:** вставте токен, згенерований на Кроці 2.
4. Натисніть **«Перевірити REST зв'язок з сервером»**.
5. Після успішного з'єднання ви побачите:
   * Зелений бейдж статусу торгівлі та активного режиму;
   * Живі KPI: нереалізований PnL, баланс, розмір маржі, кількість ботів;
   * Реал-тайм стрім позицій по WebSocket;
   * Історію виконаних угод та лог балансів.

## 4. Панель керування з локального дашборду

Зі сторінки **Live / WebSocket** локального дашборду ви можете безпечно надсилати сигнали боту на VPS:

| Кнопка / Дія | Що робить під капотом | Коли застосовувати |
|---|---|---|
| **Призупинити (Pause)** | Записує `pause=true` у `control.json` на VPS | Тимчасові технічні роботи на біржі чи оновлення |
| **Заборонити нові входи** | Записує `no_new_entries=true` | М'який вихід: відкриті позиції закриються за логікою стратегії, нові не відкриватимуться |
| **Відновити (Resume)** | Скидає всі обмеження (`pause=false`, `no_new_entries=false`, `flatten=false`) | Повернення до штатного режиму після перевірки |
| **🚨 Emergency Flatten (Kill-Switch)** | Миттєво ставить `pause=true` і закриває всі відкриті позиції | Непередбачувана поведінка ринку або екстрене закриття |

## 5. Чек-лист щоденного моніторингу

1. **Telegram-канал:**
   * Чи надходять повідомлення про закриття бару щогодини (`step`)?
   * Чи немає повідомлень про помилки підключення чи таймаути API?
2. **Перевірка розсинхрону часу:**
   * На VPS має працювати служба синхронізації часу `chrony` або `systemd-timesyncd`:
     ```bash
     timedatectl status
     ```
3. **Щотижневий аудит результатів:**
   * Раз на тиждень запустіть аудит paper vs бектест на VPS:
     ```bash
     uv run python -m scalper_hft.cli paper-audit --pair LINKUSDT:BTCUSDT
     ```
   * Переконайтеся, що максимальне просідання (Max Drawdown) не перевищує 1.5× від бектесту.

## 6. Діагностика та усунення несправностей

### 1. Помилка `Connection refused` при перевірці REST зв'язку
* **Причина:** SSH-тунель не піднято або API сервер на VPS вимкнено.
* **Рішення:** 
  1. Перевірте на VPS: `curl http://127.0.0.1:8080/api/v1/status`
  2. Перевірте локально, чи активна команда `ssh -N -L 8080:127.0.0.1:8080 ...`

### 2. Помилка `401 Unauthorized` або `Token expired`
* **Причина:** Токен застарів або `API_SECRET_KEY` на VPS відрізняється від локального.
* **Рішення:** Згенеруйте новий токен на VPS командою `uv run python -m scalper_hft.cli api token --hours 720` та вставте його в поле налаштувань дашборду.

### 3. ts_momentum портфель (iter10, long-only 1d)

Окремий paper-бот для directional momentum-портфеля (15 перпів, не pairs):

```bash
# Локально або на VPS (DRY_RUN=true обов'язково)
./scripts/paper_ts_momentum.sh --daemon

# Або напряму:
uv run python -m scalper_hft.cli paper-run-ts-momentum --daemon --sleep 3600
```

- **SQLite:** `results/paper_ts_momentum.sqlite` (pair=`TSMOM_PORTFOLIO`)
- **Pre-registration:** `docs/reports/hypothesis_ts_momentum.md`
- **Лідерборд:** `docs/reports/LEADERBOARD.md` або дашборд → «Лідерборд»
- **Аудит:** `uv run python -m scalper_hft.cli paper-audit --db results/paper_ts_momentum.sqlite`

Запускається **разом із** `pairs_arb` LINK/BTC, не замість нього.

### 4. Бот перестав оновлювати дані в базі
* **Причина:** Процес впав або завис.
* **Рішення:** Перевірте логи юніта на VPS:
  ```bash
  journalctl --user -u scalper-paper-pairs -n 50 -f
  ```
