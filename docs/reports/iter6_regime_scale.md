# Iteration 6 — regime_scale overlay для pairs_arb: A/B на 3y + 400d

Дата: 2026-09-08 · Скрипт: `experiments/iter6_regime_scale.py` · Стан: ЗАВЕРШЕНО

## Мотивація

iter4 показав, що pairs edge regime-залежний: LINK/BTC 3y +54.9% але
400d −9.65%; інші пари від'ємні на 3y. Гіпотеза: масштабування експозиції
до 0.5 у несприятливих режимах leg2 (BTC: high-vol або trend) зменшить втрати
при збереженні edge. regime_scale пере використовує існуючі пороги
`features/regimes.py` (0 нових числових параметрів → низький ризик overfitting).

## Результат A/B (regime_scale=False → True)

## Ключові висновки

1. **maxDD зменшено вдвічі на ВСІХ 5 парах** — головний ефект. Ризик-скоригований
   прибуток (ret/maxDD) суттєво покращений:
   - LINK/BTC lb=240: 1.46 → **2.64** (return майже той самий, DD вдвічі менший);
   - LINK/ETH: з від'ємного (−0.45) у **+0.44** (збиткова пара стала прибутковою).

2. **400d повернення покращено на всіх парах** (менш від'ємне / ближче до 0):
   LINK/BTC lb=120 −3.0% → −0.4%; LINK/ETH −5.9% → −0.5%. Це безпосередньо
   компенсує regime-залежність, виявлену в iter4.

3. **LINK/ETH перевернуто з −19.4% у +11.6%** на 3y — regime_scale прибрав
   втрати у несприятливих режимах BTC.

4. **WF pos fraction стабілізовано/покращено** на 4/5 пар (лише LINK/BTC lb=120
   трохи впав 65%→61%, але все ще > 60% порогу cell_audit).

5. **Трейдоф абсолютної дохідності**: на найсильнішій парі (LINK/BTC lb=120)
   3y return знизився 86%→51% через меншу експозицію. Це очікувано і
   прийнятно — Calmar ratio (ret/maxDD) майже незмінний (1.96 → 1.89).

## Робастність (анти-overfitting)

- Покращення **консистентне на всіх 5 парах** — не cherry-picking.
- 0 нових числових параметрів (пороги vol 80-й перцентиль, trend 0.35 —
  існуючі дефолти `features/regimes.py`).
- Масштаб 0.5 — єдине нове значення; чутливість до нього треба перевірити
  (0.0 / 0.25 / 0.5 / 0.75) у наступному кроці (sensitivity test).

## Наступні кроки (обов'язкові перед висновком про edge)

1. **CSCV/PBO** на LINK/BTC lb=240 з regime_scale=True (20 варіантів параметрів)
   — підтвердити, що покращення не data-snooping.
2. **Sensitivity**: масштаб 0.0/0.25/0.5/0.75 — чи плато (не пік).
3. Якщо CSCV PBO < 0.5 і smoothness > 0.30 — оновити `VALIDATED_PAIRS`
   з `regime_scale=True` та статус у `STRATEGY_STATUS.md` → validated.
4. Оновити live `pairs_engine.py` для підтримки дробового сигналу як
   size-multiplier (зараз `int(signal)` обрізає 0.5 → 0) — для
   консистентності paper-replay з бектестом перед 8-тижневим gate.

## Рекомендація

`regime_scale=True` — перспективний overlay, що матеріально покращує
risk-adjusted return pairs_arb на всіх парах без додавання параметрів пошуку.
Рекомендується до CSCV-валідації та (при PASS) включення в `VALIDATED_PAIRS`
як дефолт для paper-портфеля.
