## 4. Прогалини та знахідки

1. **`cli overfit --strategy pairs_arb` не працює.** Команда з `AGENTS.md` падає:
   `MissingDataError: pairs_arb: заявлено ['multi_symbol','ohlcv']` — `audit_cell` вантажить ОДИН
   символ, а pairs_arb потребує дві ноги. Наслідок: `_maybe_record_pair_verdict`
   (`cli/research_audit.py:145`) **недосяжний** для pairs-стратегій, тобто оновити pair-вердикт для
   fail-closed гейта `PairsPaperRunner` штатним шляхом неможливо. Для цього прогону написано
   `scripts/pair_audit.py` (WF по вікнах + DSR + CSCV/PBO + sensitivity + stress + вердикт).
2. **Розгорнутий конфіг `VALIDATED_PAIRS` (lb=120) втратив edge.** Задокументована перевалідація
   2026-09-12 (`docs/reports/cell_by_cell_audit_report.md`) показувала ret +2.52%, Sharpe 0.51,
   DD -1.28%; зараз той самий клас конфігурації дає ret +0.06%, DD -14.64% при медіанно
   від'ємному результаті по seed-ах філу. Конфіг, який у звіті 09-12 названо PASS, мав інші
   параметри (lookback 240, exit_z 0.5), а не ті, що лежать у `VALIDATED_PAIRS`.
3. **DSR = 0 в обох конфігах.** OOS Sharpe пари (per-hour) статистично незначущий після
   коригування на 27 спроб. Це узгоджується з t-NW ≈ 0.1–0.5.
4. **Критерій `stress liquidity` вироджений.** Сценарій додає `(10-1)×0.05% = 0.45%` витрат на
   КОЖЕН активний бар; при 52% експозиції за 26 281 бар це гарантоване обнулення капіталу
   (maxDD 100%) для будь-якої стратегії з безперервним утриманням позиції. Порог «stress DD >
   baseline×4» у такому вигляді відсікає всі стратегії, а не лише крихкі — калібрування потребує
   перегляду (напр., cost_mult на бар активності з обмеженням сукупної додаткової вартості).
5. **Вердикт НЕ записано у `results/audit_verdicts.jsonl`** (прогони з `--no-record`). Запис FAIL
   через `record_pair_verdict` зробив би `audit_gate_check_pair` fail-closed і заблокував
   старт/рестарт живого paper-юніта pairs — це рішення користувача, не побічний ефект аудиту.

## 5. Вердикт і рекомендації

- **Дані: PASS.** Кеш реальний, свіжий, цілісний — аудит можна проводити.
- **`pairs_arb` LINK/BTC 1h (розгорнутий lb=120): FAIL** — edge статистично незначущий,
  медіанно від'ємний під різними seed-ами філу, DSR=0, DD 14.6% при доходності 0.06% за 3 роки.
- **lb=480: FAIL** (не проходить DSR і smoothness), але це єдиний конфіг з додатним знаком,
  стійким до seed-ів — кандидат на переаудит з повним holdout, а не на live.

Рекомендовані наступні кроки:
1. Не підвищувати статус пари до live; переглянути доцільність поточного paper-юніта pairs.
2. Переаудит `lb=480` у режимі `final` (`HOLDOUT_PCT>0`, `OOS_ENFORCE_BURN=true`) з
   `pairs_arb`-сумісним шляхом + sensitivity по `exit_z` (поточний smoothness 0.122 — плато немає).
3. Додати в `pair_audit`/`pairs` явний критерій **t-NW на pooled OOS** — зараз гейт дивиться на
   частку позитивних вікон, що не є тестом значущості.
4. Перекалібрувати `liquidity`-сценарій у `validation/stress.py`.
5. Закрити прогалину п. 1 (pairs-гілка в `cli overfit`), щоб pair-вердикт оновлювався штатно.
