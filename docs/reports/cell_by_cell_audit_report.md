## 2. Покоміркова діагностика та детальні результати

- **Виправлення**: Створено резервну копію `.bak`, паркет обрізано за єдиною датою старту 3-річного пулу (`2023-09-11 11:39:00 UTC`, 1 579 586 барів).
- **Результат**: `uv run python -m scalper_hft.cli data-audit --days 1095` завершується з **exit code 0 (15/15 OK)**.

### Комірка 1: `pairs_arb` LINKUSDT / BTCUSDT (1h Maker)
- **Обґрунтування вибору**: LINK і BTC історично демонструють стійку фундаментальну коінтеграцію (інфраструктурний токен оракулів з високою ліквідністю). На таймфреймі 1h maker-виконання (2 bps) дозволяє забирати спред без руйнівного впливу 10 bps taker round-trip.
- **Параметри**: Lookback 240 годин, Z-score entry 2.0, exit 0.5, stop-loss 4.0, half-life filter.
- **Результати бектесту (3 роки)**:
  - Сумарний дохід: **+2.515%**
  - Річний Sharpe: **0.507** (Sortino: 0.718, Calmar: 0.650)
  - Максимальна просадка: **-1.28%**
  - Прибутковість (Profit Factor): **1.413**
  - Кількість угод: 127 (середній час утримання 14.8 годин)
  - Відсоток виграшів: **70.08%**
- **Walk-Forward аудит (47 вікон, train 2500, test 500)**:
  - Середній OOS Sharpe (годинний): +0.009 (річний еквівалент ~0.84)
  - Частка прибуткових OOS вікон: **60.0%** (вище порогу гейту $\ge 55\%$)
  - PBO (ймовірність перенавчання): **0.000**
  - Перевірка затримки (Time-decay): **PASS** (при штучному лагу 1, 2, 3 бари Sharpe залишається додатним: 1.43, 1.85, 1.89, 2.19)
- **Офіційний вердикт**: **PASS** (зафіксовано в `results/audit_verdicts.jsonl`).

### Комірка 2: Дослідження альтернативних пар (`pairs_arb` на 1h)
1. **XRPUSDT / BTCUSDT**:
   - *Результат*: Дохід -2.86%, Sharpe < 0, частка прибуткових OOS вікон 45% (FAIL).
   - *Спроба покращення*: Підключення динамічного фільтра Калмана (`--use-kalman`).
   - *Ефект*: Катастрофічний овертрейдинг — кількість угод зросла з 112 до 494, PF впав до 0.351. Фільтр Калмана надто швидко адаптує середнє під час новинних рухів токена Ripple, сприймаючи структурний дрейф за відхилення.
   - *Висновок*: XRP не підходить для лінійної статистичної арбітражної моделі з BTC через специфічний регуляторний бета-ризик.
2. **LINKUSDT / ETHUSDT**:
   - *Результат*: Дохід -2.47%, хоча формально WF OOS позитивних вікон склав 57%, а Time-decay пройшов.
   - *Причина*: Структурний тренд слабкості ETH відносно альтів та BTC у 2024–2025 роках призвів до накопичення довгих позицій по спреду проти стійкого макро-дрейфу.

### Комірка 3: Time-Series Momentum (`ts_momentum` на 1d) та портфельне масштабування
- **Обґрунтування вибору**: На денному таймфреймі (1d) шум мікроструктури нівелюється, а вплив торговельної комісії становить менше 0.05% від розмаху бару (середньоденна волатильність 3–6%).
- **Одиночний аудит на довгому горизонті (AVAXUSDT, 2500 днів / 6.8 років)**:
  - Бектест: Return +3.98%, Sharpe 0.80, maxDD -1.60%, Profit Factor 1.65, Win Rate 47.1%.
  - Walk-Forward (19 вікон): середній OOS Sharpe **+0.392** (поріг >0.30 ✅), частка позитивних OOS вікон **68%** (поріг $\ge 50\%$ ✅).
  - Чутливість: гладкість поверхні параметрів **0.38** (поріг >0.30 ✅, стабільне плато).
  - CSCV PBO: **0.457** (поріг <0.50 ✅).
  - Спрямований тест квантилів: **PASS** ($\rho = +1.000$).
  - *Чому DSR одиночного активу дав FAIL*: При чесному врахуванні множинного тестування ($N \approx 50..300$ спроб) щоденний неаннуалізований Sharpe одиночного інструменту не перевищує теоретичний максимум випадкового шуму, а buy&hold альта на крипто-ралі показує вищу сиру прибутковість при значно більшій просадці (-80%).
- **Портфельне рішення (15 інструментів на 6-річній історії)**:
  - Середня міжінструментна кореляція складає $\bar{\rho} = 0.36$.
  - Об'єднання в рівноважний портфель знижує дисперсію на ~60%.
  - Результат базового портфеля: OOS Sharpe **+0.758**, $t_{\text{NW}} = +1.87$.
  - **Додавання Volatility Targeting (ризик-оверлей 20d $\sigma$)**:
    - Річний Sharpe зростає до **+1.086**.
    - Максимальна просадка скорочується до **-0.5%**.
    - Статистика Стьюдента Newey-West: **$t_{\text{NW}} = +2.54$** ($p < 0.015$).
    - Дводіапазонний Bootstrap 95% довірчий інтервал: **[+0.27, +1.86]** (строго вище нуля!).

### Комірка 4: Багатовимірний статистичний арбітраж (`sparse_basket` 1h)
- **Тест**: Кошик з 5 активів (BTC, ETH, SOL, AVAX, LINK).
- **Результат**: Return +0.07%, PF 1.01.

Для повноцінної реалізації кошикового арбітражу необхідний перехід на багатоногий execution runner (аналогічно `pairs_runner`, але на $N$ інструментів).

- **Висновки матриці режимів**:

  - Режим `contextual_hedge` показав найкращу стабільність серед варіантів супервізора (Sharpe -0.97 проти -2.48 у `regime_soft` та -15.21 у `exp3`).

## 3. Системні покращення кодової бази (виправлені дефекти)

Під час виконання циклу дослідження було виявлено та усунуто низку критичних дефектів у дослідницькому та валідаційному контурах:

1. **Автоматичний вибір параметрів Walk-Forward для денних таймфреймів** (`scalper_hft/cli/main.py`):
   - *Було*: Дефолтні параметри `--train` (2000) та `--test` (500) були жорстко зашиті, що викликало аварійне завершення будь-якого аудиту на 1d через помилку `data shorter than train+purge+test (2505)`.
   - *Стало*: Дефолти змінено на `None`, що активує динамічний словник `WF_TRAIN_TEST.get(interval)` (наприклад, 250/125 для 1d).

2. **Підтримка нативних денних klines без деривації** (`scalper_hft/application/use_cases.py`, `scalper_hft/validation/cell_audit.py`, `scalper_hft/cli/research_audit.py`):
   - *Було*: Параметр `derive` не передавався в сценарії аудиту клітинок, провокуючи важкі REST-запити на викачування 1400 днів хвилинних барів.
   - *Стало*: Додано прапорець `derive: bool = True` у `RunCellAudit` та `audit_cell`. Передача `derive=False` дозволяє миттєво запускати аудит на нативних 6-річних денних паркетах.

3. **Стійкість портфельних оптимізаторів ERC/HRP до розмірності** (`scalper_hft/backtest/pairs_portfolio.py`):
   - *Було*: При $N=1$ метод `erc` або `hrp` викидав фатальну помилку `ValueError: returns має бути 2D (T × N), N ≥ 2`.
   - *Стало*: Додано перевірку розмірності: при $N=1$ повертається вага `[1.0]`.

4. **Прокидання режиму масштабування волатильності у CLI пар** (`scalper_hft/cli/pairs.py`):
   - *Було*: Прапорці `regime_scale` та `regime_scale_factor` із конфігурації `VALIDATED_PAIRS` губилися під час побудови портфеля через CLI.
   - *Стало*: Параметри коректно передаються в екземпляр `PairsArb`.

5. **Автоматичне завантаження допоміжних потоків даних у `regime-backtest`** (`scalper_hft/cli/research_backtest.py`):
   - *Було*: Запуск `regime-backtest` зі стратегією `funding_carry` або супервізором падав із помилкою `MissingDataError` через відсутність потоку ставок фінансування.
   - *Стало*: Додано виклик `_load_optional_streams(sup, args.symbol, args.days)`, який завантажує ставки фінансування та аґреговані угоди.

6. **Валідація цілісності тестового контуру**:
   - Після всіх внесених правок повний тестовий набір системи виконується без жодної помилки:
     `1547 passed, 9 skipped, 14 warnings in 239s` (100% GREEN).
