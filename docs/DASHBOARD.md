# Дашборд scalper-hft

Streamlit-інтерфейс для **дослідження**: свіжість даних, бектести, sweep, аудит
комірки, paper-журнал. Це не live-термінал і не місце для реальних ордерів.
Рахунок іде в окремому worker-процесі; дашборд ставить задачу в чергу й читає
артефакти.

## Встановлення й запуск

Потрібен extra `dashboard` і той самий Python, що й CLI (не системний /
Anaconda `streamlit` з PATH — там немає пакета `scalper_hft`):

```bash
uv pip install -e ".[dashboard]"
uv run python -m scalper_hft.cli dashboard
```

Опції:

- `--port N` — порт Streamlit (за замовчуванням 8501).
- `--no-worker` — не піднімати research worker разом із UI. Тоді задачі
  залишаться в `queued`, доки не запустите воркер окремо:

```bash
uv run python -m scalper_hft.cli job worker --jobs 2
```

Без `--no-worker` CLI сам стартує один worker, якщо heartbeat ще немає, і
зупиняє його разом із дашбордом.

Відкрийте в браузері адресу, яку надрукує Streamlit (зазвичай
`http://localhost:8501`).

## Що має бути готовим

| Потрібно | Навіщо |
|---|---|
| Кеш 1m (parquet у `data/` або PostgreSQL) | Бектест і sweep читають бари з кешу, не з біржі на кожен rerun |
| `DRY_RUN=true` у `.env` | Режим paper/research; бейдж LIVE на «Моніторингу» означає, що dry-run вимкнено |
| Worker | Будь-яка кнопка «поставити в чергу» інакше лише запише рядок у SQLite |
| Комісії в `.env` | Maker 0.02% / taker 0.05% / slippage; бектест без комісій не є edge |

Список символів на дашборді — канонічний універсум (`CANONICAL_SYMBOLS`), не
обов’язково `DEFAULT_SYMBOLS` з `.env`. Пари для `pairs_arb` — окремий
курований список (лише перевірені коінтеграцією).

Параметри стратегії з UI зараз завжди дефолти класу (`params: {}`). Інші
значення — через CLI `--param`.

## Архітектура в двох реченнях

Дашборд **не рахує** важкі бектести в процесі Streamlit. Він пише job у
`results/jobs.sqlite`; worker виконує kind (`backtest`, `pairs`, `sweep`,
`overfit`, `capacity`) і кладе parquet/JSON у `results/jobs/<id>/`. Sweep
додатково пише `results/sweep.db`. Paper pairs читається з
`results/paper_pairs.sqlite`.

```
Кеш (1m) → worker (backtest / sweep / overfit) → артефакти → сторінка UI
```

## Перший прогін

1. Сторінка **Моніторинг**: якщо 1m «немає» або «застарілий» — оновіть кеш
   (кнопка в рядку або масове «Оновити застарілі»).
2. Сторінка **Задачі**: бейдж «воркер активний». Якщо ні — запустіть worker
   або перезапустіть дашборд без `--no-worker`.
3. **Бектест**: оберіть стратегію / символ (або пару) / ТФ / глибину →
   «Запустити бектест». Статус з’явиться на цій сторінці й у «Задачах».
4. Після `succeeded` дивіться KPI, графік, угоди. Для одиночної стратегії —
   Deflated Sharpe і вкладки аналітики; для `pairs_arb` — спред + equity.
5. Не робіть висновок про edge з одного in-sample прогону: **Дослідження →
   Аудит комірки** (walk-forward + DSR + sensitivity).

## Сторінки

Навігація зліва: Моніторинг, Бектест, Дослідження, Задачі, Довідка.

### Моніторинг

Дослідницький бриф: чи свіжі дані, що вже в книзі стратегій, чи paper
підтверджує бектест.

- **Бейджі** — dry-run / LIVE, біржа, maker vs taker, parquet vs Postgres,
  комісії та розмір позиції з `.env`.
- **Книга стратегій** — консолідований статус (валідована / дослідження /
  відхилена / чекає даних). Це не один бектест; джерело —
  `docs/STRATEGY_STATUS.md` (копія в коді, не парсинг markdown).
- **Свіжість кешу** — один рядок на символ. Свіжий < 2 год, старіючий < 24 год,
  далі — застарілий. Застарілий кеш = ризик lookahead на «сьогоднішніх»
  висновках. Дії: оновити хвіст 1m, розширити історію (префікс), видалити
  parquet. У режимі Postgres видалення стирає лише файли в `data/`, не таблиці.
- **Paper pairs** — fill-rate, equity по парах, місячний PnL (стоп після двох
  збиткових місяців поспіль). Немає файлу — спочатку
  `uv run python -m scalper_hft.cli paper-replay-pairs`.
- **Останній sweep** — топ клітинок за **OOS Sharpe** (fallback — in-sample).
- **Paper-run CSV** — `results/paper_equity_*.csv`.

Якщо worker мовчить, кеш дірявий або немає paper DB — з’являться підказки з
посиланнями на Задачі / Довідку.

### Бектест

Сайдбар: стратегія, символ або пара, таймфрейм, глибина днів.

- **Запустити бектест** — `submit` у чергу. Той самий fingerprint не дублює
  succeeded/queued/running (кнопка «Перезапустити задачу» — `force=True`).
- Після успіху — дохідність, Sharpe (год.), угоди, hurdle комісій (чи середня
  угода покриває round-trip). Для одиночних стратегій — Win rate, profit
  factor, **Deflated Sharpe** (> 0.95 ≈ значущий edge після поправки на
  кількість trials). Для пар — DSR з equity returns і графік **спреду**
  (маркери входу/виходу, позиція, equity).
- Клік по маркеру ▲/▼/× відкриває деталі угоди (для одиночних стратегій).
- Вкладки аналітики (одиночні): метрики / фільтри (потрібен job з
  `trace=True`) / MAE/MFE / сесії UTC.
- **Діагностика**: cohort decay і stress рахуються з уже завантаженого
  результату. **Capacity** (Sharpe при масштабі позиції ×1…×10) — окрема
  задача `capacity` у черзі, не синхронний прогін у браузері.

### Дослідження

Зверху — **спільні** стратегія / символ / таймфрейм / днів. Вони живлять
атрибуцію фільтрів, порівняння equity, якість угод, аудит і режими. Sweep
має власні multiselect (пакетний прогін).

Розділи (лише активний рахується на rerun):

1. **Sweep matrix** — enqueue `sweep` (backtest або walk-forward). Heatmap і
   таблиця з `results/sweep.db`. Resume не перераховує вже виконані клітинки.
2. **Filter attribution** — бектест з `trace=True`. Скільки сигналів зрізав
   кожен фільтр і **shadow PnL** (що було б без фільтра). Детальний трейс
   зараз реалізовано для `mean_reversion`; інші стратегії дають порожній
   FilterTrace.
3. **Порівняння equity** — кілька backtest-задач, нормалізовані криві (база
   1.0) і кореляція денних дохідностей. Криві тримаються в сесії як посилання
   на fingerprint, не як перерахунок у UI.
4. **Якість угод** — MAE/MFE, heatmap година×день UTC, розподіл PnL з
   артефактів бектесту.
5. **Топ комбінації** — фільтр по Sharpe / угодах / win rate; сортування за
   OOS Sharpe якщо є. «Відкрити бектест», «Поставити аудит у чергу», CSV.
6. **Аудит комірки** — walk-forward + Deflated Sharpe + sensitivity. PASS
   лише якщо всі пороги overfitting-audit виконано (`kind=overfit`).
7. **Режими** — розбивка угод по vol / structure / `structure|vol`. Це
   in-sample атрибуція, не OOS-вердикт.

### Задачі

Черга `results/jobs.sqlite`. Фільтри за статусом і типом. Рядок — людський
підпис (стратегія · символ · ТФ), не сирий JSON.

- Скасувати (queued/running), перезапустити (`force`), хвіст `job.log`.
- **Відкрити результат**: backtest / pairs / capacity → Бектест з
  підставленням параметрів; overfit → аудит комірки; sweep → матриця.
- Fragment оновлюється кожні 2 с. «воркер мовчить» = немає свіжого heartbeat.

### Довідка

Цей файл плюс живі бейджі (dry-run, worker, шляхи jobs/sweep).

## Типові сценарії

**Оновити дані й прогнати валідовану пару**

1. Моніторинг → фільтр «застарілі» → «Оновити застарілі» (хвіст 1m).
2. Бектест → `pairs_arb` → наприклад `XRPUSDT/BTCUSDT` → 1h → 90 днів →
   maker (так і ставиться для пар).
3. Дивитись hurdle (дві ноги) і графік спреду. Один гарний Sharpe ≠ дозвіл
   на live.

**Знайти комбінацію в sweep і перевірити OOS**

1. Дослідження → Sweep matrix: кілька стратегій × символів × ТФ, режим
   walkforward, Resume увімкнений.
2. Топ комбінації: min OOS Sharpe / угод → оберіть рядок → «Поставити аудит
   у чергу».
3. Аудит комірки: PASS/FAIL, вікна WF, smoothness sensitivity.

**Чи фільтр не зрізає прибуток**

1. Спільний рядок: `mean_reversion`, символ, 15m.
2. Filter attribution → поставити в чергу.
3. Shadow avg PnL > 0 і win rate > 50% → фільтр, ймовірно, шкідливий на цій
   вибірці (все одно потрібен OOS).

**Порівняти дві криві**

1. Додати криву A (спільні параметри + мітка).
2. Змінити стратегію або символ → додати криву B.
3. Чекати `succeeded` у Задачах; на графіку з’являться нормалізовані equity
   і кореляція, коли є щонайменше дві успішні криві.

## Глосарій

| Термін | Що означає |
|---|---|
| **Freshness** | Вік останнього 1m бара: свіжий (< 2 год), старіючий (< 24 год), застарілий, немає, майбутнє (годинник/TZ) |
| **Fill-rate** | `filled / (filled + unfilled)` у paper pairs. Низький fill з’їдає maker-edge |
| **Hurdle** | Maker round-trip × кількість ніг. Середня угода вже після комісій має бути вищою |
| **Sharpe (год.)** | Річний Sharpe, оцінений з годинних (або барних) returns; не плутати з «сирим» in-sample |
| **OOS Sharpe** | Середній Sharpe на тестових вікнах walk-forward. Головна метрика sweep |
| **OOS+** | Частка OOS-вікон з додатним Sharpe |
| **DSR (Deflated Sharpe)** | Поправка на кількість trials. Пороги UI: > 0.95 значущий, > 0.50 слабкий |
| **MAE / MFE** | Максимальний рух проти / на користь за життя угоди. Efficiency = ret / MFE; < 50% — ранній вихід |
| **Shadow PnL** | Forward-return заблокованого сигналу. Додатний → фільтр відкидає прибуткові входи |
| **Fingerprint** | SHA-256 від kind + канонічних params. Та сама задача не ставиться вдруге без force |
| **Capacity** | Sharpe при масштабі позиції ×1…×10; точка насичення — де edge ламається від impact |
| **Cohort decay** | Метрики угод по місяцю входу; падіння PnL при стабільній кількості = «тиха» смерть edge |
| **Stress** | Сценарії crash / liquidity / vol_spike / funding_shock на історичних returns |

## Troubleshooting

**`ModuleNotFoundError: scalper_hft`**
Запущено `streamlit` не з venv проєкту. Завжди:
`uv run python -m scalper_hft.cli dashboard`.

**Задача висить у queued**
Worker не запущений або heartbeat старший за ~15 с. Сторінка «Задачі» /
бейдж на Довідці. Команда: `uv run python -m scalper_hft.cli job worker`.

**«Ще немає задачі з цими параметрами»**
Натисніть «Запустити». Якщо задача вже succeeded з тим самим fingerprint —
результат підтягнеться без нового прогону; «Перезапустити» перерахує.

**Немає даних для графіка**
Немає 1m/ресемплу для символу й ТФ. Моніторинг → завантажити або
`uv run python -m scalper_hft.cli download --symbol BTCUSDT --interval 1h --days 90`.

**Filter attribution порожній**
Стратегія без `generate_signals_traced`. Працює `mean_reversion`. Sweep з
«Filter tracing» пише агрегат у sweep store, не обов’язково повний трейс.

**pairs_arb без свічок**
Так і задумано: графік — **спред** (log-ratio), не OHLC однієї ноги.

**Видалив кеш, а в Postgres дані лишились**
Діалог на Моніторингу стирає parquet у `data/`. Рядки `klines` / `funding` /
`agg_trades` не чіпає.

**Книга стратегій розходиться зі свіжим звітом**
Книга — ручна копія статусу, не live-метрики з останнього job.
