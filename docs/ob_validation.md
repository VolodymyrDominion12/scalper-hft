# Валідація OB-стратегій на реальних даних стакана

Результати ітерації 3: валідація `ob_imbalance` на реальних bookTicker/depth5
снапшотах Binance USDT-M futures.

## Збір даних

```bash
# bookTicker (best bid/ask + об'єми) — ~200 снапшотів/сек
python -m scalper_hft.cli record-bookticker --symbol BTCUSDT --minutes 60
# depth5 (5 рівнів стакана, оновлення кожні 100 мс)
python -m scalper_hft.cli record-bookticker --symbol BTCUSDT --minutes 60 --depth
```

Рекордер: UTC-мітки, flush у parquet батчами, автоперепідключення при розриві стріму.

## Ключові висновки (реальні дані, BTCUSDT)

1. **Top-of-book imbalance вкрай біполярний**: |imb| > 0.5 у ~77% снапшотів
   (std ≈ 0.77). Перший рівень стакана домінується поодинокими великими
   ордерами (walls) → сигнал шумний.
2. **Depth5 imbalance теж екстремальний** (|imb| > 0.5 у ~59%), але стабільніший
   завдяки усередненню 5 рівнів.
3. **Висновок**: для OB-стратегій потрібні:
   - усереднення imbalance у часі (EMA/ковзне вікно, z-score з lookback);
   - зважена глибина (ваги за рівнями);
   - фільтр спреду/ліквідності.
   Один снапшот top-of-book як сигнал — недостатньо (підтверджено емпірично).

## Валідація стратегії

`ObImbalanceScalper` на 1m барах з реальним imbalance: 181 бар з даними,
угоди відкриваються (win rate 67% на 3 угодах) — але обсяг даних замалий
для статистичних висновків. Потрібні години запису.
