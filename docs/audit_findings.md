# Висновки аудиту: виправлення funding-обліку (ітерація 4)

## Що сталося

Paper-replay (валідація risk-шару на історії) виявив **серйозний баг обліку
funding у бектест-рушії**: ставка фандінгу нараховувалася КОЖЕН бар замість
одного разу за період ставки (Binance: кожні 8 год). Для 1m-барів це
завищення ≈ 480×.

## Наслідок

Попередній висновок ітерації 2 про funding_carry був АРТЕФАКТОМ багу:

| Символ | Було (баг, ітер. 2) | Стало (виправлено, ітер. 4) |
|---|---|---|
| BTCUSDT | +3.34% | −0.10% |
| ETHUSDT | +2.00% | −0.05% |
| SOLUSDT | +3.29% | −0.54% |

Після виправлення:
- funding внесок при 1% позиції ≈ **0.0067%** за 90 днів (0.67% при 100%) —
  не покриває ціновий дріфт (−4.5% при 100%: стратегія нетто-шорт під час ралі);
- walk-forward: avg OOS Sharpe **−0.35**, 33% вікон > 0;
- Deflated Sharpe: **DSR = 0.000** → edge НЕ підтверджено;
- висновок: **стратегія відхилена** (як і mean_reversion/cvd_momentum).

## Чому це добре для системи

Це саме той випадок, для якого будувався цикл інвестігейт → реалізація → тест →
аудит → покращення: перехресна валідація різними шарами (бектест vs paper-replay
vs контрольний юніт-тест) впіймала помилку, яка інакше дала б хибний "зелений"
сигнал до live-торгівлі.

## Як уникнути повторення

1. **Юніт-тест** `test_funding_charged_once_per_block`: funding впливає рівно на
   один бар, розмір = ставка.
2. **Paper-replay** як обов'язковий крок перед висновком про edge: він використовує
   той самий шар виконання, що й live (комісії, funding-платежі, риск-ліміти).
3. **Контрольні цифри**: funding за період ≈ n_stavok × rate × position_pct
   (ручний розрахунок, див. `docs/ob_validation.md` — ті самі підходи).

## Поточний статус стратегій (ітерація 4, усі чесні)

| Стратегія | Вердикт |
|---|---|
| mean_reversion (+regime) | ⚠ відхилено (OOS < 0, DSR = 0) |
| cvd_momentum (реальні aggTrades) | ⚠ відхилено (fee-drag, PF < 0.3) |
| funding_carry | ⚠ відхилено після виправлення обліку (OOS < 0, DSR = 0) |
| market_maker | ⚠ експериментальна, потребує L2-калібрування |
| ob_imbalance | ⚠ потребує накопичення bookTicker/depth5 даних |

**Висновок циклу**: жодна з сигнальних стратегій не пройшла аудит — це чесний
результат; система готова до пошуку edge, а не до live. Наступні кандидати:
delta-neutral funding arb (перп+спот), depth-weighted OB після накопичення даних,
maker-стратегії з L2.
