# Скіл: Контроль ризиків, сайзинг та виконання (Risk & Execution Management)

## Мета
Забезпечити безпечне виконання торгових сигналів, коректне калібрування розміру позиції (position sizing), захист капіталу від неочікуваних просідань та проведення paper/live торгівлі без витоку ключів чи неконтрольованих збитків.

---

## 1. Залізні правила безпеки Live торгівлі

> [!CAUTION]
> 1. **За замовчуванням завжди `DRY_RUN=true`**:
>    Будь-який тестовий або демонстраційний запуск виконується виключно в емуляційному (paper) режимі.
>    Реальні ордери на біржу можуть відправлятися **виключно за явною прямою вказівкою користувача** після успішної паперової валідації.
> 2. **Жодних секретів у коді чи логах**:
>    API-ключі зберігаються виключно в `.env` (доданому до `.gitignore`).
>    Усі конфігурації зчитуються через `scalper_hft.config.get_settings()`.
>    Сервери MCP та CLI інструменти ніколи не повертають секретні ключі назовні.

---

## 2. Моделі сайзингу та фільтри ризиків

Система scalper-hft підтримує динамічний сайзинг:
1. **Volatility-Scaled Sizing (EWMA/ATR)**:
   - Розмір позиції обернено пропорційний поточній волатильності: при зростанні волатильності позиція зменшується для збереження постійного risk-budgeting.
2. **HMM Regime Filtering**:
   - Hidden Markov Model визначає поточний ринковий стан (Trend / Mean-Reversion / High-Vol Noise).
   - При вході в несприятливий або занадто хаотичний режим розмір позиції зменшується до нуля (блокування нових входів).
3. **Hard Stop & Drawdown Protection**:
   - Перевірка максимальної денної просадки (`MAX_DAILY_DRAWDOWN_PCT`). При досягненні ліміту всі відкриті позиції закриваються, а нові блокуються до наступного торгового дня.

---

## 3. Запуск Paper Trading та моніторингу

```bash
# Запуск paper торгівлі парного арбітражу:
uv run python -m scalper_hft.cli live --strategy pairs_arb --dry-run

# Запуск одного кроку paper-торгівлі для перевірки стану:
uv run python -m scalper_hft.cli step --strategy pairs_arb --symbol BTCUSDT

# Перевірка безпечного резюме налаштувань ризиків:
uv run python -m scalper_hft.cli settings
```

---

## 4. Звірка позицій (Reconciliation)

Перед кожною новою ітерацією виконання:
1. Звірити локальний облік позицій із реальними позиціями на біржовому акаунті Binance USDT-M.
2. При виявленні розбіжностей (desync):
   - Зафіксувати алерт у логах.
   - Скасувати непідтверджені лімітні ордери.
   - Синхронізувати локальний стан за біржовим снепшотом.
